Core Web Vitals are a set of measurements Google uses to describe how a page feels to a real visitor: how fast the main content loads, how quickly it responds to input and how stable the layout is while loading. They are one of several page experience signals, so they will not rescue weak content, but they can help close the gap between similar pages and they directly affect conversions.

## The three metrics

- Largest Contentful Paint (LCP): how long it takes for the main content, usually a large image or heading block, to appear. Google considers 2.5 seconds or less to be good.
- Interaction to Next Paint (INP): how quickly the page responds when a user taps, clicks or types. A score of 200 milliseconds or less is considered good.
- Cumulative Layout Shift (CLS): how much the layout jumps around while loading. A score of 0.1 or less is considered good.

## Where to check

Use PageSpeed Insights for any URL and the Core Web Vitals report in Google Search Console for site-wide groups of pages. Look at field data, which reflects real visitors, and treat lab data as a diagnostic tool.

## Common fixes for slow LCP

Compress and correctly size your largest images, serve modern formats, avoid lazy-loading the main hero image, use a decent hosting plan and a caching setup, and remove render-blocking scripts you do not need.

## Common fixes for poor INP

Reduce heavy JavaScript, remove unnecessary plugins and third-party scripts such as chat widgets and trackers you do not use, and avoid long tasks that block the page from responding.

## Common fixes for layout shift

Set explicit width and height on images and embeds, reserve space for ads or banners, and load fonts in a way that avoids sudden text jumps.

## Keep it in proportion

Fix the worst offenders on your most important pages first, such as your homepage and top service pages. A faster page usually converts better regardless of its effect on rankings, so the work pays for itself in more enquiries, not only in search performance.
